# 开发记录

## 2026-09-23 — 排查「买入次日就被卖掉」：不是乱卖，是「自动执行」默认开着

**用户反馈**：有 bug，买进去第二天就卖掉了。

**排查（不猜，拿真实 K 线对账）**：写诊断脚本，用 stub 从 `chart.setOption` 里截获真实 K 线，逐笔核对每次「触发卖出」：

- 80 次买入中 5 次（6.3%）在次日被纪律卖出：止损 4 / 止盈 1；
- **每一笔都能在当日 K 线上找到依据**：
  - 买 214.29、止损 203.58 → 次日最低 199.9，按设定价 203.58 成交（−5.00%）；
  - 买 141.91、止损 134.81 → 次日**跳空低开 132.53** → 按开盘价成交（−6.61%）；
  - 买 24.82、止损 23.58 → 次日最低 23.5，按设定价 23.58 成交（−5.00%）。
- 成交价口径正确（盘中触及按设定价 / 跳空按开盘价）。

→ 结论：**逻辑没错，是「自动执行」默认开着**（`EXIT_DEF.on = true`）。配上默认 5% 止损，在"近一年至少涨停过一次"的活跃股池里，次日打个 −5% 就会被真的扫出去。对玩家来说，"我什么都没点，仓位就没了"体验上等同于 bug。

**修复（3 处）**：

1. `EXIT_DEF.on` 默认改为 **false** —— 线只是纪律参考，到价卖不卖由玩家自己点「卖」。**自动下单这种行为的默认值不该是"开"。**
2. 存档 key 升到 `pangan_trainer_exit_v2` 并做迁移：旧档（v1）的止损/止盈**百分比保留**，但 `on:true` **不继承**（回归默认关）—— 否则已经受影响的玩家升级后照旧被代卖。
3. 线上标签 `· 已停` → `· 手动`（说清是"你自己动手"而不是"功能坏了"）；面板 tip / 游戏内帮助页 / README.md / README.txt 同步写明「默认关闭，勾了才自动卖」。

**验证**（Node + DOM stub，15 项断言全过）：

| 检验 | 结果 |
|---|---|
| 新档默认「自动执行」关闭，且不改设置就不写档 | ✅ |
| 50 局买入后 0 次被系统卖出（其中 1 次价格确实穿越了线，系统没动手） | ✅ |
| 旧档迁移：纪律 8% / 16% 保留，`on:true` 不继承 | ✅ |
| 勾选后 150 局共 3 次触发，当日 K 线全部对得上 | ✅ |
| 成交价 = 设定价（盘中）/ 开盘价（跳空）；收益率与纪律一致 | ✅ |
| 拖动改价位、连打 20 局零异常 | ✅ |

**踩坑**：第一版诊断脚本把「日志最新一行」当买入行读 —— 但"买入次日就触发"时，最新一行已经变成触发行，于是把**止损成交价当成了买入价**，反算出错误的止损位，误报一片"方向不符"。日志是倒序渲染的，取「最近一次买入」必须按关键字找，不能直接取第一行。**诊断工具自身的假设，也要先被验证。**

## 2026-09-23 — 修正：止损 / 止盈线只在持仓时出现

**用户反馈**：不要一直显示止损止盈线 —— 买进去之后才可以设置，空仓也显示线是不行的。

**问题**：上一版把「随时可改」做过了头 —— 空仓时也画两条按最新价折算的参考线，侧栏控件常驻可编辑，还专门做了一整套「空仓参考位」逻辑。但止损止盈本质是**持仓纪律**：没有仓位时设线毫无意义，反而在图上多堆两条与当前决策无关的线，干扰看图。

**改法（5 处）**：

1. `renderExitLayer()`：`S.shares <= 0` 直接隐藏整层 —— 没建仓，图上一条线都不出现。
2. `renderExitPanel()`：空仓时 `inStop / inTake / exitOn` 全部 `disabled`，面板加 `.exit.lock` 置灰，文案改为「空仓 — 买入后才能设置止损 / 止盈」。
3. 输入 / 拖动 / 开关三个 handler 各加 `if(S.shares <= 0) return;` 兜底 —— 不依赖 DOM 的 `disabled` 状态，逻辑层也守住。
4. 删掉「空仓参考位」那套：`exitRefPrice()` 只在持仓时返回买入价，空仓一律返回 0。跨局保留的百分比纪律仍保留，在买入那一刻折算成两条价位。
5. HTML 里控件默认带 `disabled` + `lock`（与空仓态一致）；游戏内帮助页 / README.md / README.txt 同步改写。

**验证**（Node + DOM stub 跑真实游戏代码，21 项断言全过）：

| 检验 | 结果 |
|---|---|
| 空仓：无线 + 三个控件全锁 + 置灰 + 文案提示 | ✅ |
| 空仓改输入 / 拖线：一律无效 | ✅（买入后止损价仍是 买价×0.95） |
| 买入后：线与解锁同时出现，价位 = 买价 × 纪律 | ✅ |
| 持仓中拖线改价位 | ✅ |
| 手动卖出 / 触发纪律 / 结算后：线消失 + 面板重新锁上 | ✅ |
| 再次买入：线重现且沿用上次纪律（−3% → 新买价×0.97） | ✅ |
| 连打 20 局零异常 + 跨局累计 | ✅ 21 条 |

**踩坑**：测试脚本第一版用 `lastLog()` 从日志行数组**末尾往前**找「最近一次」记录，但日志是**倒序渲染**的（最新一条在最前），于是永远取到最旧的一条，把第二次买入的成交价取成了第一次的 —— 假失败。**找「最近一次」必须跟着渲染顺序走。**

## 2026-09-23 — 止损 / 止盈升级为「图上可拖动的价位线」

**用户需求**：图上的止损止盈线，玩家可以随时设置。

**原状**：侧栏只有两个百分比输入框（默认 −5% / +10%），买入时按买入价折算成两条 `markLine` 虚线。
问题有三个：

1. `markLine` 只能看不能拖 —— 玩家想改价位只能回侧栏敲数字，敲的还是百分比，不是他心里的价位；
2. 空仓时根本不画线（`if(S.shares > 0)`），也就是「设置」只能在上一次买入后、下一次买入前盲填；
3. 执行口径读的是百分比 × `entryPrice`，一旦玩家想在盘中微调，没有任何抓手。

**改法（4 层）**：

| 层 | 做法 |
|---|---|
| 图上 | 弃用 `markLine`，改为覆盖在 `#chart` 上的透明 DOM 层（`.exlayer` + 两条 `.exline`），价位 → 像素用 `chart.convertToPixel({yAxisIndex:0}, price)` 换算 |
| 交互 | 按住线上下拖：`mousedown/touchstart` → `document` 上的 `mousemove/mouseup`；`touch-action:none` + `preventDefault` 保证手机上不误滚页面 |
| 口径 | 持仓时锁定绝对价位 `S.stopPrice / S.takePrice`（执行与画线只看它），拖线 = 反算百分比存进纪律；空仓时不维护价位，参考位按最新价现算 |
| 联动 | 面板输入百分比 → `syncExitPrices()` 折算价位；拖线 → `pctFromExitPrice()` 反算百分比。两个方向共用 `EX_RANGE`（止损 1~50%、止盈 1~300%） |

**关键设计**：

- **拖动时只改 DOM，不重画图表。** 松手才 `commitExitPrice()` + `render()`。每帧 `setOption` 既卡，又会因为 Y 轴 `scale:true` 自适应变化让指针下的线乱跳。验证脚本对这一点专门断言（拖动中 `setOption` 调用数为 0）。
- **两条线的合法区间互不重叠**（止损恒在参考价下方、止盈恒在上方）→ 永远满足「止损 < 止盈」，不用额外的冲突校验，也顺手挡掉了「把止损拖到止盈上面」这种自相矛盾的设置。
- **Y 轴 `scale:true` 会随滚轮缩放变化** → 给 chart 绑 `dataZoom` 事件重新定位两条线，否则缩放后线会漂。
- 价位离视野太远时线贴到主图边缘（tag 里仍是真实价位），不会跑到成交量副图里。
- 隐藏层的尺寸每次 `renderExitLayer()` 都从 `#chart` 的 `offsetLeft/Top/Width/Height` 重新同步，不假设布局。

**验证**（Node + DOM stub 跑真实游戏代码，21 项断言全过）：

| 检验 | 结果 |
|---|---|
| 买入后两条线价位 = 买入价 ×(1∓纪律%) | ✅ |
| 拖动止损线后价位跟随、百分比同步反算 | ✅ |
| 拖动中不重绘图表 / 松手才重绘一次 | ✅ 0 次 → 1 次 |
| 边界夹取（止损 −50%、止盈 +300%） | ✅ |
| 输入框改百分比 → 线的价位重算（双向联动） | ✅ |
| 纪律真的被执行（成交价与设定价位一致） | ✅ 触发止损 69.35 = 设定 69.35 |
| 空仓时拖线改纪律 / 设置跨局保留 | ✅ |
| 连打 20 局零异常 + 跨局累计写入 | ✅ 21 条记录 |

**踩坑**：验证脚本第一版拿「触发后」的面板值当期望值 —— 那时仓位已清，面板显示的是空仓参考位，导致假失败。**断言必须取事件发生前的快照。**

## 2026-09-23 — 股票池全部换成「有涨停的活跃股」

**用户反馈**：随机抽到的行情全是"无行情"的冷门股，要求只从至少涨停过一次的股里挑。

**数据核查**：原 27 只池子里**只有 5 只**（隆基、中免、紫金、韦尔、五粮液）近一年有过收盘涨停，其余 22 只是银行 / 白酒 / 公用事业等低波动蓝筹 —— 随机抽到无行情股的概率约 **81%**，反馈属实。若直接把池子筛到 5 只，几局就会重复。

**修复（两层）**：

1. **重建数据池（27 → 68 只）**：从腾讯行情接口批量拉取 86 只人气活跃股候选（券商并购 / AI 算力 / 光模块 / 半导体存储 / 机器人 / 固态电池 / 核聚变 / 军工 / 华为链 / 稀土 / 信创 / 创新药 / 并购重组），按「近一年至少一次收盘涨停」筛选：
   - 涨停口径：主板 ±10%，创业板 / 科创板 ±20%，北交所 ±30%，ST ±5%；前复权价格留 0.2% 舍入容差。
   - 保留 63 只有涨停的（含德明利 20 次、合锻智能 19 次、莲花控股 18 次的高频妖股），加原池 5 只涨停股；剔除无涨停的 20 只（同花顺、中际旭创、新易盛、寒武纪等白马）和区间异常的 3 只（中航电测 / 岩石股份 / 高鸿股份，长期停牌或旧区间）。
   - 每只取最近 250 根，剔除当日未收盘K线，最后交易日统一为 2026-09-22。

2. **涨停日锚定抽样**：`newGame()` 不再纯随机长度 —— 随机选一个落在决策期 `[WARMUP+3, len-MIN_TAIL]` 内的涨停日，把局长拉到至少盖住它；该股涨停全在预热历史的（如紫金矿业）退回随机长度。

**验证**（60 局模拟）：

| 检验 | 结果 |
|---|---|
| 完整对局异常 | **0 / 60** |
| 决策期内遇到涨停 | **58 / 60（97%）**，其余 2 局涨停在开局预热历史里（图上可见） |
| 可见历史含涨停 | **60 / 60** |
| 抽样多样性 | 60 局抽到 **42 只**不同标的 |

**踩坑**：`_build.js` 直接覆盖 `game-data.js` 后重跑，把新池误当"原池"二次叠加（出现重复股票）→ `git checkout -- game-data.js` 恢复后重跑。**改写数据文件的构建脚本必须幂等，或显式区分源与目标。**

## 2026-09-23 — 修复「白屏 / 假死」故障

**症状**（用户截图）：打开页面后图区**全空**（连坐标轴都没有），代码显示 `??????`，进度 `0 / 0`，出手 `0 笔`，日志停在初始文案 —— 看起来页面卡死，且**没有任何错误提示**。

**病根**：图表库原本从 CDN **同步**引入：

```html
<script src="https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js"></script>
```

CDN 不通时 `echarts` 未定义 → `newGame()` 里的 `render()` 在 `echarts.init()` 处抛异常 →
而 `renderStats()` 排在 `render()` **后面** → 状态条永远停在 HTML 里的初始占位值
（`100,000` / `空仓` / `0 / 0` / `0 笔` / `??????`），控制台之外的玩家看不到任何线索。

**复现**（Node + DOM stub 跑真实游戏代码，不依赖浏览器）：

| 场景 | 结果 |
|---|---|
| 有 echarts + 有数据 | 正常：1 次 `setOption`，状态条更新为 `SIM-XXXX` / `1 / N` |
| `echarts` 未定义 | `echarts is not defined` → 图空 + 状态条冻结 ← **与截图完全一致** |
| `GAME_DATA` 未定义 | `Cannot read properties of undefined (reading 'stocks')` → 同样冻结 |

**修复（5 处）**：

1. **图表库本地化**：新增 `echarts.min.js`（5.5.1，1.03 MB），`<script src="echarts.min.js">` 引入，**不再依赖 CDN，离线可玩**。
2. **多源回退**：本地文件缺失 / 损坏时，依次尝试 jsdelivr → unpkg → bootcdn。
3. **启动调度**：主脚本包成 `__BOOT__()`，等图表库解析完再启动；**图表库彻底挂掉也照常启动**（状态条 / 日志 / 买卖按钮都能用）。
4. **顶部错误提示条**：`window.onerror` 兜底 + 两处前置检查（行情数据缺失、图表库缺失），都在页面顶部红色横幅里写明**原因和处理办法**。
5. **顺序与容错**：`renderStats()` 提到 `render()` 之前（状态条不再依赖画图成功）；`render()` / `revealAll()` 在图表库缺失时直接返回而不是抛异常。

**验证**：

- 四条路径（正常 / 图表库全挂 / 数据缺失 / 异步回退后仍失败）全部零异常，且失败路径都有明确横幅提示。
- 60 局完整对局回归：异常 **0 / 60**（含结算页与复盘页渲染）。

**教训**：外部依赖必须做失败路径设计。「白屏 + 无提示」比「报错」糟糕得多 —— 前者让用户只能来问人，后者自己就说清了。

## 版本 v1.0 — 2026-09-22

首个可玩版本。

### 交付内容

| 文件 | 大小 | 说明 |
|---|---|---|
| `index.html` | 46.7 KB | 单文件游戏本体，内联 CSS + JS |
| `game-data.js` | 319.1 KB | 27 只 A 股 × 250 根日 K |
| `README.txt` | 3.8 KB | 玩家向说明 |

### 数据层

- 数据源：`westock-data-skillhub`（前复权日 K）。
- **单次拉取上限 250 根日 K**，因此每只股票取 250 根。
- 区间：2025-09-11 → 2026-09-22。
- 股票池 27 只，覆盖金融 / 消费 / 科技 / 新能源 / 医药 / 周期 / 农业。
- 字段结构：`[日期, 开盘, 最高, 最低, 收盘, 成交量]`。

### 游戏设计

- **逐日推进**：玩家点一次「过」前进一天，不是自动播放。
- **匿名标的**：显示为 `SIM-XXXX`，结算后才揭示真实代码与名称。
  - 理由：知道标的会让玩家调用记忆而非判断，练的是背题不是盘感。
- **三动作**：买 / 卖 / 过。单一持仓，全仓进出，不支持分批。
- **零未来函数**：任何时点只能看到已发生的 K 线。

### 三轮修复（按发生顺序）

#### 修复 1：择时评分基准口径错误（最严重）

**症状**：随机乱点居然跑出 **+1.10% 的 alpha**，且只有 41.2% 的概率跑输"开局躺平"。

**病根**：原基准是「开局买入持有」。但随机策略 75% 的时间处于空仓，而**空仓在一只不涨的票上会自动跑赢满仓**。于是评分系统系统性地奖励"少动手"这个伪技巧，而不是奖励判断力。

**修复**：改用**暴露匹配基准（exposure-matched benchmark）**：

```javascript
var totalDays = S.idx - WARMUP + 1;
var holdDays = 0;
S.trades.forEach(function(t){
  var end = (t.exitIdx !== null) ? t.exitIdx : S.idx;
  holdDays += (end - t.entryIdx);
});
var exposure = totalDays > 0 ? clamp(holdDays / totalDays, 0, 1) : 0;
var baseMatch = baseRet * exposure;   // 按持仓占比折算的基准
var alpha     = ret - baseMatch;      // 择时超额
```

**验证**（三项自洽检验全部通过）：

| 检验 | 期望 | 实测 |
|---|---|---|
| 全程观望 alpha | 0.00% | ✅ 0.00% |
| 买入持有 alpha | ≈ 0 | ✅ ≈ 0（最大偏离 0.365%） |
| 随机交易 alpha（1080 样本） | 0，正负对称 | ✅ 均值 −0.05%，负占比 51.6% |

#### 修复 2：K 线随进度被压扁

**症状**：推进越深，K 线越细，最后形态完全看不清。

**病根**：`render()` 用 `S.bars.slice(0, S.idx+1)` 把**全量历史**塞进固定宽度图 → 单根宽度 = 图宽 ÷ K线数。这是把"无未来函数"错误实现成了"显示全部历史"。

**修复**：改为**滑动窗口**，只渲染最近 N 根：

```javascript
var VISIBLE_BARS = 70;
function render(){
  var all = S.bars.slice(0, S.idx+1);
  var start = Math.max(0, all.length - VISIBLE_BARS);
  var bars  = all.slice(start);
  // MA 必须用全量历史算完再切窗，否则窗口左端的 MA 会错
  var ma5All = [], ma20All = [];
```

### 评分体系

| 维度 | 算法 |
|---|---|
| 买点评分 | `(区间最高 − 买入价) / (区间最高 − 区间最低) × 100`，窗口取买入后 `LOOKAHEAD` 根 |
| 卖点评分 | `100 − (卖出价 − 区间最低) / (区间最高 − 区间最低) × 100` |
| 扛回撤舒适度 | `100 + 最大浮亏% × 5`，clamp 到 [0,100] |
| 择时超额 | 见修复 1 的暴露匹配公式 |
