## 2026-10-28 — 选股改成「主板 + 开局近 8 日有涨停 + MA5 向上」

**用户要求**：选股有问题 —— 要找出当日最近 8 个交易日内有涨停过的、且五日均线向上、主板的票。

**原状**：池子是「近一年至少一次涨停」的 68 只（含创业板/科创板/北交所/ST），
而且用了一个**未来函数**的抽样方式：在整局区间里随机锚定一个涨停日，把局拉长到覆盖它。
从玩家视角看，这不是「开局时这只票刚涨停过」，而是「这局里将来一定会遇到涨停」。

**改法**：

1. 新增 `isMainBoard()`：沪 600/601/603/605、深 000/001/002 为主板；排除创业板 300、科创板 688、北交所、ST。
2. 新增 `hasLimitUpInRecent(st, idx, 8)`：截至当日（含）的最近 8 个交易日里有没有收盘涨停。
3. 新增 `ma5Up(st, idx)`：当日 MA5 > 昨日 MA5。
4. `eligiblePicks()` 枚举所有「股票 + 开局日」组合并缓存，`newGame()` 从里面随机抽一个；
   同时删掉原来的「涨停日锚定」逻辑（那是拿未来数据选股）。
5. 起点不再固定在第 60 根 → 新增 `S.startIdx`，进度显示、复盘基准（躺平基准、暴露天数）全部改用它，
   否则「第几天 / 共几天」和收益率基准都会错。

**代价与取舍**：固定第 60 根开局时，只有 **4 只**主板股同时满足三个条件（太重复）；
放开「开局日也一起选」后是 **49 只股票、889 个组合**，池子够大。所以开局日由选股结果决定，不再固定。

**验证**（Node + DOM stub，7 项全过，30 局）：

| 检验 | 结果 |
|---|---|
| 30 局全部是主板（无创业板/科创板/北交所/ST） | ✅ |
| 30 局开局日往前 8 个交易日内都有收盘涨停 | ✅ |
| 30 局开局日 MA5 都向上 | ✅ |
| 池子多样性：30 局覆盖 19 只不同股票 | ✅ |
| 从未满足条件的 6 只票一次都没出现 | ✅ |
| 开局进度显示 1 / N（起点改用 startIdx） | ✅ |

**踩坑**：验证脚本第一版靠「x 轴日期序列」反推是哪只股票 —— 但所有股票共用同一交易日历，
前 N 天日期完全一样，于是永远匹配到列表第一只（隆基绿能），造成「30 局都是同一只、条件全不满足」的假失败。
改成用 **OHLC 价格序列**匹配才唯一。

## 2026-10-28 — 止损 / 止盈可以只设一个（各自独立开关）

**用户反馈**：不是一买就同时设止损止盈 —— 有时候只设止损，有时候只设止盈，这些都要考虑进去。

**原状**：执行判定写死了「两条都必须有效」——`if(!isFinite(stopP) || !isFinite(takeP)) return null;`，
只要少一条，整笔的纪律卖出直接失效；面板也强制两个输入框并存，玩家没法表达「这次只要止损」。

**改法（5 处）**：

1. 新增 `S.stopOn / S.takeOn` 两个独立开关（面板上每条纪律前一个小勾），写进 v2 存档；旧档没有这两个字段时默认都开，行为不变。
2. `syncExitPrices()` 只给**启用**的那一边折算价位，关掉的一边置 `null`。
3. `checkExitTrigger()` 改成逐边判断：有止损就查跌、有止盈就查涨，互不牵连；两边都没有直接返回 `null`（纯手动）。
4. `renderExitLayer()` 只画启用的线；两边都关时整层隐藏，不留空壳。
5. 面板：关掉的一边输入框置灰、盈亏比显示「仅止损 / 仅止盈 / 未设」，持仓文案显示「未设止损 / 未设止盈」；两边都关时「自动执行」也置灰。

**顺手修了一个真 bug**：`isFinite(null) === true`（`Number(null)` 是 0）。价位用 `null` 表示「这一边没设」，
于是 `isFinite(S.stopPrice)` 会把「没设」误判成「已设、价位 0」—— 关掉止盈后线不消失、面板还可能显示 0.00。
新增 `isNum(v)`（`typeof v === 'number' && isFinite(v)`），把 8 处判断全部换掉。

**验证**（Node + DOM stub，27 项全过）：

| 检验 | 结果 |
|---|---|
| 关止盈：存档写入、线隐藏、输入框置灰、盈亏比「仅止损」 | ✅ |
| 只设止损：12 天内从未触发止盈，跌破止损正常卖出 | ✅ |
| 关止损：线隐藏、盈亏比「仅止盈」 | ✅ |
| 只设止盈：从未触发止损，涨到止盈正常卖出 | ✅ |
| 两个都关：整层隐藏、自动执行禁用、任何行情都不卖 | ✅ |
| 开关跨局保留；空仓时两个勾都禁用 | ✅ |
| 重新勾上两边：价位 / 线 / 盈亏比全部恢复 | ✅ |
| 连打 20 局（交替开关止盈）零异常 | ✅ |

**踩坑**：验证脚本第一版直接读 `S` 想断言状态 —— 但游戏代码整个包在 `__BOOT__()` 闭包里，`S` 不是全局。
改成只通过 UI（勾选状态、`style.display`、面板文案）和 `localStorage` 观察，反而更接近真实用户路径。

## 2026-10-23 — K线支持按住左键拖动平移（看得见更早的K线）

**用户反馈**：鼠标左键可以移动K线，有时候看不到前面和后面的K线。

**病根**：上一版为了保证「单根K线宽度恒定」，`render()` 只把最近 `VISIBLE_BARS` 根传给 ECharts —— 图上**根本没有更早的数据**，dataZoom 再怎么拖都没东西可翻；而且 `moveOnMouseMove:false`，左键拖动本来就是关的。

**改法（5 处）**：

1. `render()` 改为传入**全部历史**（截至当前日），由 dataZoom 把**默认视窗**锁在最近 N 根：
   `start = (1 - N/all.length) * 100`。默认观感完全不变（70 根、单根宽度恒定），但左边有内容可以翻。
2. `dataZoom`：`moveOnMouseMove:true`（按住左键拖动平移）、保留 `zoomOnMouseWheel:true`（滚轮缩放）、
   加 `minValueSpan:15`（最少保留 15 根，防止缩成一条线）。
3. **记住用户视图**：`chart.on('dataZoom')` 把 start/end 存进 `zoom`，之后的重新渲染（比如拖止损线触发的）沿用用户的视图，
   不会弹回最新；用 `_applyingView` 标志区分「程序化 setOption」和「用户操作」。
4. 左下角新增 **「最新」** 按钮一键复位；切换 40/70/110 档、点「过」进入新一天、开新局都会重置到最新。
5. markPoint / markArea 改用**日期坐标**（原来依赖窗口内偏移 `t.entryIdx - start`，全量数据后必须改）。

**验证**（Node + DOM stub，17 项全过）：

| 检验 | 结果 |
|---|---|
| 数据全量传入（开局 61 根 → 推进后 121 根） | ✅ |
| 默认视窗恰好显示 70 根（数据不足时全显示） | ✅ |
| `moveOnMouseMove:true` / 滚轮缩放 / 最少 15 根 | ✅ |
| 用户拖到 30%~55% 后，拖止盈线触发的重绘沿用了该视图 | ✅ |
| 「最新」复位、40/110 档切换、推进一天回最新 | ✅ |
| 连打 20 局（反复平移）零异常 | ✅ |

## 2026-10-23 — 新增大盘参照：上证指数日K + 情绪读数

**用户需求**：需要大盘的分时图和日K，用来判断当时的情绪（上证指数）。

**数据可得性调研（本次主要工作）**：把常见的免费行情源都试了一遍，结论是**整年历史分时拿不到**：

| 源 | 结果 |
|---|---|
| 东财 `push2his ... klt=101`（日K） | ✅ 整段可取：250 根，OHLC 自洽，与个股区间对齐 |
| 东财 `klt=5 / 15 / 60`（分钟） | ❌ 只保留最近 15~20 个交易日；带 `beg/end` 回溯返回空 |
| 腾讯 `kline/mkline` m5 | ❌ 只给最近几百根；带日期区间报 `param error` |
| 腾讯 `day/query`、`minute/query` | ❌ 忽略 date 参数，只给当天 / 最近 5 天 |
| 新浪 `getKLineData scale=5` | ❌ 上限 1023 根（约 21 天） |
| 雪球 `chart/kline.json` | ❌ 需要登录 token（error_code 400016） |
| 网易历史分时 / 新浪 MinLine | ❌ 502 / Service not found |

游戏区间是 2025-09-11 ~ 2026-09-22，而分钟数据只覆盖最近 15~20 天 —— **完全没有交集**，所以不可能内置真分时，也不该用合成数据冒充。

**交付（4 块）**：

1. `market-data.js`：上证指数 250 根真实日K（与个股同一交易日口径，14 KB）。
2. **顶栏胶囊**：当前游戏日期的点位、涨跌幅、近 20 日 sparkline，随「过」实时更新。
3. **大盘弹层**：近 120 根日K + MA5/MA20，竖线标「今天」；卡片给出收盘 / 当日涨跌 / **收盘在当日振幅的位置** / 近 20 日；情绪读数再对比这只票当天与大盘是**同向还是反向**。
4. **用「收盘位置」代替分时表达日内强弱**：`(close−low)/(high−low)` —— 0% 收在最低、100% 收在最高。数据真实，只是粒度到日级；弹层里明确标注了这个限制。

**无未来函数**：指数数据一律按 `date <= 当前游戏日期` 截断；验证脚本断言「图表最后一根 === 游戏当前日期」。

**验证**（Node + DOM stub，20 项全过）：

- 指数覆盖个股**决策期**（第 61 根起）全部 **12920** 个交易日，缺失 0；
- 胶囊随日期推进更新、sparkline 正常；
- 弹层渲染、复用图表实例、打开时快捷键不穿透；
- 连打 20 局（反复开合大盘）零异常。

**边界**：个股数据里 2 只票（双成药业、松发股份）多出 2025-09-10 一天，而指数从 09-11 开始 —— 但开局固定在每只票第 61 根，这一天永远不会成为「当前日期」，不影响任何对局。

**未做**：分时图。若后续拿到可用的历史分时数据（CSV/JSON，[时间, 收盘] 即可），在 `market-data.js` 里补一个 `minutes` 字段就能接上，弹层加个 tab。

## 2026-09-23 — 排查「买入次日就被卖掉」：不是乱卖，是「自动执行」默认开着

**用户反馈**：有 bug，买进去第二天就卖掉了。

**排查（不猜，拿真实 K 线对账）**：写诊断脚本，用 stub 从 `chart.setOption` 里截获真实 K 线，逐笔核对每次「触发卖出」：

- 80 次买入中 5 次（6.3%）在次日被纪律卖出：止损 4 / 止盈 1；
- **每一笔都能在当日 K 线上找到依据**：
  - 买 214.29、止损 203.58 → 次日最低 199.9，按设定价 203.58 成交（−5.00%）；
  - 买 141.91、止损 134.81 → 次日**跳空低开 132.53** → 按开盘价成交（−6.61%）；
  - 买 24.82、止损 23.58 → 次日最低 23.5，按设定价 23.58 成交（−5.00%）。
- 成交价口径正确（盘中触及按设定价 / 跳空按开盘价）。

→ 结论：**逻辑没错，是「自动执行」默认开着**（`EXIT_DEF.on = true`）。配上默认 5% 止损，在"近一年至少涨停过一次"的活跃股池里，次日打个 −5% 就会被真的扫出去。对玩家来说，"我什么都没点，仓位就没了"体验上等同于 bug。

**修复（3 处）**：

1. `EXIT_DEF.on` 默认改为 **false** —— 线只是纪律参考，到价卖不卖由玩家自己点「卖」。**自动下单这种行为的默认值不该是"开"。**
2. 存档 key 升到 `pangan_trainer_exit_v2` 并做迁移：旧档（v1）的止损/止盈**百分比保留**，但 `on:true` **不继承**（回归默认关）—— 否则已经受影响的玩家升级后照旧被代卖。
3. 线上标签 `· 已停` → `· 手动`（说清是"你自己动手"而不是"功能坏了"）；面板 tip / 游戏内帮助页 / README.md / README.txt 同步写明「默认关闭，勾了才自动卖」。

**验证**（Node + DOM stub，15 项断言全过）：

| 检验 | 结果 |
|---|---|
| 新档默认「自动执行」关闭，且不改设置就不写档 | ✅ |
| 50 局买入后 0 次被系统卖出（其中 1 次价格确实穿越了线，系统没动手） | ✅ |
| 旧档迁移：纪律 8% / 16% 保留，`on:true` 不继承 | ✅ |
| 勾选后 150 局共 3 次触发，当日 K 线全部对得上 | ✅ |
| 成交价 = 设定价（盘中）/ 开盘价（跳空）；收益率与纪律一致 | ✅ |
| 拖动改价位、连打 20 局零异常 | ✅ |

**踩坑**：第一版诊断脚本把「日志最新一行」当买入行读 —— 但"买入次日就触发"时，最新一行已经变成触发行，于是把**止损成交价当成了买入价**，反算出错误的止损位，误报一片"方向不符"。日志是倒序渲染的，取「最近一次买入」必须按关键字找，不能直接取第一行。**诊断工具自身的假设，也要先被验证。**

## 2026-09-23 — 修正：止损 / 止盈线只在持仓时出现

**用户反馈**：不要一直显示止损止盈线 —— 买进去之后才可以设置，空仓也显示线是不行的。

**问题**：上一版把「随时可改」做过了头 —— 空仓时也画两条按最新价折算的参考线，侧栏控件常驻可编辑，还专门做了一整套「空仓参考位」逻辑。但止损止盈本质是**持仓纪律**：没有仓位时设线毫无意义，反而在图上多堆两条与当前决策无关的线，干扰看图。

**改法（5 处）**：

1. `renderExitLayer()`：`S.shares <= 0` 直接隐藏整层 —— 没建仓，图上一条线都不出现。
2. `renderExitPanel()`：空仓时 `inStop / inTake / exitOn` 全部 `disabled`，面板加 `.exit.lock` 置灰，文案改为「空仓 — 买入后才能设置止损 / 止盈」。
3. 输入 / 拖动 / 开关三个 handler 各加 `if(S.shares <= 0) return;` 兜底 —— 不依赖 DOM 的 `disabled` 状态，逻辑层也守住。
4. 删掉「空仓参考位」那套：`exitRefPrice()` 只在持仓时返回买入价，空仓一律返回 0。跨局保留的百分比纪律仍保留，在买入那一刻折算成两条价位。
5. HTML 里控件默认带 `disabled` + `lock`（与空仓态一致）；游戏内帮助页 / README.md / README.txt 同步改写。

## 2026-09-23 — 止损 / 止盈升级为「图上可拖动的价位线」

**用户需求**：图上的止损止盈线，玩家可以随时设置。

**原状**：侧栏只有两个百分比输入框（默认 −5% / +10%），买入时按买入价折算成两条 `markLine` 虚线。
问题有三个：

1. `markLine` 只能看不能拖 —— 玩家想改价位只能回侧栏敲数字，敲的还是百分比，不是他心里的价位；
2. 空仓时根本不画线（`if(S.shares > 0)`），也就是「设置」只能在上一次买入后、下一次买入前盲填；
3. 执行口径读的是百分比 × `entryPrice`，一旦玩家想在盘中微调，没有任何抓手。

**改法（4 层）**：

| 层 | 做法 |
|---|---|
| 图上 | 弃用 `markLine`，改为覆盖在 `#chart` 上的透明 DOM 层（`.exlayer` + 两条 `.exline`），价位 → 像素用 `chart.convertToPixel({yAxisIndex:0}, price)` 换算 |
| 交互 | 按住线上下拖：`mousedown/touchstart` → `document` 上的 `mousemove/mouseup`；`touch-action:none` + `preventDefault` 保证手机上不误滚页面 |
| 口径 | 持仓时锁定绝对价位 `S.stopPrice / S.takePrice`（执行与画线只看它），拖线 = 反算百分比存进纪律；空仓时不维护价位，参考位按最新价现算 |
| 联动 | 面板输入百分比 → `syncExitPrices()` 折算价位；拖线 → `pctFromExitPrice()` 反算百分比。两个方向共用 `EX_RANGE`（止损 1~50%、止盈 1~300%） |

**关键设计**：

- **拖动时只改 DOM，不重画图表。** 松手才 `commitExitPrice()` + `render()`。每帧 `setOption` 既卡，又会因为 Y 轴 `scale:true` 自适应变化让指针下的线乱跳。验证脚本对这一点专门断言（拖动中 `setOption` 调用数为 0）。
- **两条线的合法区间互不重叠**（止损恒在参考价下方、止盈恒在上方）→ 永远满足「止损 < 止盈」，不用额外的冲突校验，也顺手挡掉了「把止损拖到止盈上面」这种自相矛盾的设置。
- **Y 轴 `scale:true` 会随滚轮缩放变化** → 给 chart 绑 `dataZoom` 事件重新定位两条线，否则缩放后线会漂。
- 价位离视野太远时线贴到主图边缘（tag 里仍是真实价位），不会跑到成交量副图里。
- 隐藏层的尺寸每次 `renderExitLayer()` 都从 `#chart` 的 `offsetLeft/Top/Width/Height` 重新同步，不假设布局。

**验证**（Node + DOM stub 跑真实游戏代码，21 项断言全过）：

| 检验 | 结果 |
|---|---|
| 买入后两条线价位 = 买入价 ×(1∓纪律%) | ✅ |
| 拖动止损线后价位跟随、百分比同步反算 | ✅ |
| 拖动中不重绘图表 / 松手才重绘一次 | ✅ 0 次 → 1 次 |
| 边界夹取（止损 −50%、止盈 +300%） | ✅ |
| 输入框改百分比 → 线的价位重算（双向联动） | ✅ |
| 纪律真的被执行（成交价与设定价位一致） | ✅ 触发止损 69.35 = 设定 69.35 |
| 空仓时拖线改纪律 / 设置跨局保留 | ✅ |
| 连打 20 局零异常 + 跨局累计写入 | ✅ 21 条记录 |

**踩坑**：验证脚本第一版拿「触发后」的面板值当期望值 —— 那时仓位已清，面板显示的是空仓参考位，导致假失败。**断言必须取事件发生前的快照。**

## 2026-09-23 — 修复「白屏 / 假死」故障

**症状**（用户截图）：打开页面后图区**全空**（连坐标轴都没有），代码显示 `??????`，进度 `0 / 0`，出手 `0 笔`，日志停在初始文案 —— 看起来页面卡死，且**没有任何错误提示**。

### 三轮修复（按发生顺序）

#### 修复 1：择时评分基准口径错误（最严重）

**症状**：随机乱点居然跑出 **+1.10% 的 alpha**，且只有 41.2% 的概率跑输"开局躺平"。

**病根**：原基准是「开局买入持有」。但随机策略 75% 的时间处于空仓，而**空仓在一只不涨的票上会自动跑赢满仓**。于是评分系统系统性地奖励"少动手"这个伪技巧，而不是奖励判断力。

**修复**：改用**暴露匹配基准（exposure-matched benchmark）**：

```javascript
var totalDays = S.idx - WARMUP + 1;
var holdDays = 0;
S.trades.forEach(function(t){
  var end = (t.exitIdx !== null) ? t.exitIdx : S.idx;
  holdDays += (end - t.entryIdx);
});
var exposure = totalDays > 0 ? clamp(holdDays / totalDays, 0, 1) : 0;
var baseMatch = baseRet * exposure;   // 按持仓占比折算的基准
var alpha     = ret - baseMatch;      // 择时超额
```

**验证**（三项自洽检验全部通过）：

| 检验 | 期望 | 实测 |
|---|---|---|
| 全程观望 alpha | 0.00% | ✅ 0.00% |
| 买入持有 alpha | ≈ 0 | ✅ ≈ 0（最大偏离 0.365%） |
| 随机交易 alpha（1080 样本） | 0，正负对称 | ✅ 均值 −0.05%，负占比 51.6% |

#### 修复 2：K 线随进度被压扁

**症状**：推进越深，K 线越细，最后形态完全看不清。

**病根**：`render()` 用 `S.bars.slice(0, S.idx+1)` 把**全量历史**塞进固定宽度图 → 单根宽度 = 图宽 ÷ K线数。这是把"无未来函数"错误实现成了"显示全部历史"。

**修复**：改为**滑动窗口**，只渲染最近 N 根：

```javascript
var VISIBLE_BARS = 70;
function render(){
  var all = S.bars.slice(0, S.idx+1);
  var start = Math.max(0, all.length - VISIBLE_BARS);
  var bars  = all.slice(start);
  // MA 必须用全量历史算完再切窗，否则窗口左端的 MA 会错
  var ma5All = [], ma20All = [];
  for(var i=0;i<all.length;i++){ /* 全量计算 */ }
  var ma5  = ma5All.slice(start);
  var ma20 = ma20All.slice(start);
  // 标记点/阴影/成交量做 -start 索引平移，并判断是否落在窗内
}
```

补充：K 线加 `barWidth:'62%'`，并新增 40 / 70 / 110 根三档切换。

**验证**：窗口填满后单根宽度锁定 **17.1px**，第 21 天与第 103 天的宽度波动比 **1.0000x**（完全一致）。
